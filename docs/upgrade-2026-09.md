# 2026 年 9 月版本升级说明

本次复查以 `d92240c` 为新版、`e949807` 为主要对比基线。线上实例的实际提交和部署配置需由维护者核对。

## 升级配置

1. 升级前备份数据库、`.env` 和现有镜像版本。两位维护者应使用同一份部署配置。
2. `SESSION_SECRET` 和 `CRYPTO_SECRET` 均必须显式设置，至少 32 个字符，且两者不能相同。Compose 现在会把这两个值传入容器；缺失时会在启动前报错。已有合规密钥继续沿用，不要在每次部署时重新生成。
3. 如旧版只有 `SESSION_SECRET`，请按 `.env.example` 配齐配置。修改 `SESSION_SECRET` 会使原有登录会话失效。多节点必须使用相同密钥；Electron 的 `secrets.env` 也需要持久保存，文件损坏时应恢复原文件。
4. 反向代理部署应设置 `TRUSTED_PROXIES` 为实际代理 IP/CIDR。未配置时，新版忽略转发 IP 头，限流和令牌 IP 白名单将看到代理地址。HTTPS 部署设置 `COOKIE_SECURE=true`；纯 HTTP 本地调试保持 `false`。
5. 主分支推送生成 `:edge` 镜像，标签构建（含手动指定已有标签运行发布工作流）才更新 `:latest`。默认 Compose 使用 `:latest`，因此主分支推送不代表线上已经升级。
6. 用户链接抓取恢复使用 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`，发送前仍验证目标 URL。直连在启用域名 IP 过滤时还会校验实际拨号 IP；经代理请求的远端 DNS 与网络访问由运营者配置的代理控制。`apply_ip_filter_for_domain=false` 会同时关闭域名在请求前和拨号时的 IP 过滤，但不关闭 IP 字面量的过滤。

## 本次修复

- OAuth 绑定使用新版会话中的用户 ID，避免绑定操作误变成登录或注册；登录不再继承上一账号的安全验证状态，2FA 数据库查询失败时拒绝建立新登录。
- 修复用户列表中 `group` 保留字未引用造成的查询失败，同时保留敏感字段过滤和角色限制。
- 令牌额度更新真实返回数据库错误；无限额度令牌仍记录预扣，避免结算和退款产生负使用量或额外余额；追加钱包预扣同样检查可用余额。
- 订阅退款与退款状态在同一事务内提交，避免 SQLite 死锁以及部分成功后重复退款。
- 透传压缩媒体时保留 `Content-Encoding`，并继续过滤 Cookie、CORS 和逐跳响应头。
- 账单缓存按用户隔离，避免会话过期后换账号仍显示上一个账号的记录；修复日志页遗漏类型文件、已移除支付功能的残留类型和钱包按钮类型错误。
- Electron 密钥文件读取或写入失败时停止启动，不再使用无法持久化的临时密钥继续运行。
- 修复干净检出时 CI 缺少前端嵌入文件的问题；前端使用冻结锁文件安装并验证两套生产构建。
- 同步两套前端锁文件与已有依赖清单，构建工具统一固定 Bun 1.4.2。
- 更新 Go WebSocket、图片与文本依赖，修复漏洞扫描报告的可达问题；构建使用 Go 1.26.8，生产 Docker 镜像固定版本与摘要。

计费修复不修改额度单位或自动重算历史余额、令牌使用量。若新版已经产生统计或退款异常，需结合请求和消费日志核对历史记录。

## 发布前验证

仓库 CI 执行 Go 构建、`go vet ./...`、`go test ./...`、认证/计费相关包的竞态检查、漏洞扫描、密钥扫描、默认前端类型检查、账单隔离与 Electron 密钥测试，以及两套前端生产构建。数据库测试以临时 SQLite 为主；MySQL/PostgreSQL 迁移测试需要分别提供 `TEST_MYSQL_DSN` 和 `TEST_POSTGRES_DSN`。

本次额度与退款回归在 SQLite、关闭 Redis 的条件下执行，覆盖数据库写入失败、订阅退款回滚与幂等、无限额度令牌结算和追加预扣余额不足；不等同于已验证生产 Redis 或 MySQL/PostgreSQL 的多节点并发。

上线前在测试环境确认：已有账号登录、2FA、OAuth 绑定、用户列表、令牌预扣/结算/失败退款，以及现有渠道的普通和流式请求。真实上游服务和线上数据库需在部署环境验证。
